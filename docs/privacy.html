DrHelix App Privacy Policy

Last updated: October 21, 2026

This notice describes the native DrHelix macOS app. It does not replace the privacy notices of Adobe, Microsoft, GitHub, Apple, or other services you choose to access through the app.

Your organization and site data

DrHelix is an administrative client for Adobe Experience Manager Edge Delivery Services and Adobe Commerce. It sends the requests you initiate, and requests needed to load the interface, to the relevant service using your account's permissions. The app does not send your administrative data to a separate DrHelix-operated backend.

Organization names, selected sites, interface preferences, and the analytics preference are stored locally in app preferences. Helix and Commerce authentication secrets are stored in the macOS Keychain. Newly created site access token values are shown for you to save; DrHelix does not save or log them. If you choose to copy information, it is placed on the system clipboard.

Usage analytics

Starting with version 1.0.1, DrHelix uses TelemetryDeck to understand app sessions and feature usage. Analytics are enabled by default, but do not start before you accept the preview agreement on launch.

You can stop new analytics collection at any time by turning off Settings > Privacy > Share usage analytics. Your choice is saved across launches. With analytics disabled at launch, the analytics SDK is not initialized.

When enabled, analytics signals include:

  • A hashed, randomly generated installation identifier and a random session identifier. DrHelix does not use your login email, account name, or account ID as the analytics identifier.
  • Session/install events and session/retention statistics.
  • Fixed sidebar feature names, such as the selection of Manage Site, and a fixed distribution label identifying Direct or internal/TestFlight builds. These events describe navigation, not whether an API operation succeeded.
  • App and build versions, macOS version, device model and architecture, screen information, locale, time zone, language, and appearance/accessibility preferences supplied by the SDK.

DrHelix does not supply organization or site names, email addresses, credentials, token IDs or values, request URLs, request or response contents, or status-log messages to TelemetryDeck. Analytics requests use a separate ephemeral network session without Helix or Commerce cookies or stored credentials.

Analytics are used to understand and improve DrHelix, not for advertising or cross-app tracking. TelemetryDeck processes the signals according to its privacy information and privacy policy. Network providers necessarily handle connection metadata when receiving requests.

Disabling analytics stops new signals and cancels pending analytics network requests. It cannot recall data already delivered. The SDK can retain previously collected signals locally for delivery; those signals may be sent if you enable analytics again. Uninstalling the app or disabling analytics should not be assumed to delete data already processed by a service provider.

Updates and other network services

Direct-download builds use Sparkle to check an update feed hosted on GitHub Pages and download signed app updates from GitHub. Internal builds receive updates through TestFlight instead. These providers receive normal request/connection metadata under their own privacy policies.

Signing in and using administrative features communicates with the authentication and API services involved. The general-purpose request tool communicates with the URLs you enter. Review the destination and do not send credentials or confidential information to untrusted services.

Questions and changes

For privacy questions, use the contact routes on the DrHelix project. Do not post credentials, personal information, or private administrative data in public issues. This notice may be updated as the app changes; the date above identifies the current revision.
